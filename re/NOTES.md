## Container / requirements
- `SQUARE.EXE` 204,457 B = MZ stub + **PMODE/W v1.22** (copyright 1994-1996, Daredevil and Tran) + `PMW1` overlay at file offset 0x2730 (stub image = file[0x40:0x2730], MZ SS = SEG+0x356, entry 0x5e).
  Same route as pls_amb: `unpack_pmodew.py` (copied unchanged: runs the stub under Unicorn, PMODE/W loader reads the EXE through DOS) with args `EXE 0x2730 0x356 OUT`. `unpack_clean.py OUT.bin` stops at the program entry and dumps 64 MB.
- Program entry **0x3b1b8** (`jmp short`, string "WATCOM C/C++32 Run-Time system" at 0x3b1ba; Watcom 1995 RTL, also has "RATIONAL DOS/4G" strings from the RTL, but the extender is PMODE/W). Flat model: **CS=0x860, DS=SS=0x858, ES=0x58 (not 0x868/0x860 as in AMBROZIA!)**, GDT at 0x1b700 (limit 0x86f), PSP = LDT selector 0x24 (cstart `mov ax,24h`), initial ESP 0x14b110. `0x868`/`0x8` in the loader are 16-bit loader code selectors: a first attempt hooked "first INT with high ESP" and dumped the loader still reading the EXE.
- `emucore.py` = pls_amb's, only the selectors/GDT/entry/ESP changed (`sed`-level). DOS/DPMI/VBE stubs unchanged, VBE is simply not used. Needs: 386+FPU (Watcom FPU code everywhere), **VGA mode 13h then unchained (mode X-like: ports 3c4/3c5 map mask, 3d4 CRTC start address)**, MIDAS Sound System 0.7.b1 (same menu as AMBROZIA: 12 x Down (0,0x50) + Enter (13) = "No Sound"; `emucore` keybytes), module `squademo.xm`, `square.pak`, `midas.cfg` optional.
- Credits string in the binary: "demo (c) alex evans 1997", "demo by alex `statix' evans (c) 1997" (the engine is Statix' 1997 code, reused). Command line: `-h`, `-c` (configure sound), `-r` (reverb off), press both shift keys = screenshot to `shotNNNN.bmp` (BMP writer present). Startup text: "ingesting...", then PAK open, then "life takes time ......" (precalc, dots).
- Whole demo = ~15 scene functions called one after another from `main` (0x1c37d.. region, return value tested with `call 0x3b15d` = abort check): 0x2f7d7, 0x29a81, 0x366f2, 0x305f7, 0x1faa1, 0x2edbd, 0x31f0a, 0x28f64, 0x243a9, 0x34674, 0x33b7e, 0x32a9a(0xb00), 0x2f420, 0x338a5, 0x32a9a(0xc0c), 0x390ab. Data names used (strings 0x101000-0x102500): canyon (.fpl/.fbp/.fad), molecules (caffeine, ecstasy, c6h12o5, dna .mol), pinblob, cubes (rayes, back2, cube.fad), planet/plnt (sunflare, plnt.gst/.fad), brain/senseof/braino2 (dunetex), tunnel (krol1..3, repsh, fond), bjork (cr1..5, palflow, 3bulbe/3spike/1bulbe/1spike .dat), plasma, title/gst, people.lzw + logo.raw, zebou.lzw / secret.raw (the "secret zebou" scene), beat.dat, font.raw, compo2.raw...

## Timing / music link (found, harness not written yet)
- 0x1c059 = wrapper of `MIDASgetPlayStatus(&st)` (callee 0x3a07c, struct at 0x10ce00 {order, pattern, row,...}); copies to 0x10ce20 (order), 0x10ce1c (row) and **0x10ce28 = order*64 + row** (song position used by the effects, e.g. `cmp [0x10ce28],0x2c`).
- 0x1c14c = `MIDASsetTimerCallbacks(60000 mHz = 60 Hz, 0, 0, 0x1c0a3, 0)`: ISR callback **0x1c0a3** = run the registered per-tick callbacks (`0x1ca79(1)`) then `inc [0x10ce4c]` (frame/tick counter). Callback registry (8 slots): fn table 0x111bfc, tick stamp 0x111c1c, arg 0x111c3c; 0x1c9c5(fn, arg) registers, 0x1ca49(fn) removes, 0x1ca79(arg) runs the ones with that arg, 0x1cab2 runs them once per elapsed tick (catch-up loop) and returns the elapsed ticks (animation dt).
  => like AMBROZIA the demo is a function of (music position, tick counter, callbacks); a harness needs: virtual 60 Hz clock, `MIDASgetPlayStatus` replaced by `xm_times/squademo.json` (`xmtime.py SQUADEMO.XM`, 263.0 s, 56 orders), and the ISR callbacks 0x1c0a3 injected per tick (nested emu_start from a hook is not tried yet; alternative: call it between scene polls).
- Display: back buffer pointers [0x10d188] (320-wide, +0xa00 = 8 guard rows, 0x4c400 B) and [0x10d18c] (0x10e00 B); 0x1cb4d(0x13) = set mode; 0x1cbaf = switch to unchained mode (map mask 0xf02 on 0x3c4, clear 64 K at 0xa0000, CRTC writes); the copy to VGA planes is not located yet. Capturing the screen needs either a planar VGA model in the harness (write hook on 0xa0000, map mask, CRTC start) or a hook on the flip routine reading the back buffer + DAC (ports 3c8/3c9 like pls_amb's harness).
- 0x29a81 (first scene function, the one running at the first poll): FPU code, 320x480 table loop at 0x29ea8..0x29f21 (reads three byte tables, `dst = tex[(a*4+b)<<8 + c]`), calls trig helper 0x3b700 (Watcom float->int/`fistp` wrapper) and 0x2c25b (textured quad/line drawer with 6 args).

## Session 5 (people scene completed, blur ported)
- **Zoom blur 0x2a8e8 + asm 0x58000 ported bit-exact: `web/js/blur.js`** (`re/blur_gold.py` captures per call cx, cy, arg3, arg4, p, S and the 320x200 buffer before/after; `node tools/cmp_blur.mjs DIR`: 120 calls, 0 differing pixels). Algorithm: tx[x]=trunc((x-cx)*64*arg4), ty[y] likewise; T[i]=round-to-even(i*arg3) low byte; for every pixel a bilinear sample at (x+tx>>6, y+ty>>6) with 6-bit fractions where the weight table 0x121924 is simply W[f][d]=trunc(d*f/64)&255 (no table needed), result added saturating to the destination in place. Order: columns left of cx for all rows from cy upward, then columns from cx rightwards for those rows, then the same for rows cy+1 downward (the in-place order matters). Note: my earlier note put the table at 0x122424, it is 0x121924.
- **Blur arguments**: cx = 50*N(0x86,t)+160, cy = 50*N(0x48,t)+100, t = p/2, arg3 = min(S*0.42+0.5, 0.93), arg4 = -0.028; N(e,t) = sum over 3 terms of sin((tab[e]+64)*s8*t + tab[e+1]-64)*(tab[e+2]+64)*s10 (s10 starts .005 and halves, s8 starts .001 and doubles), tab = bytes at 0x110be4 (rand()&0x7f at start-up). The guest x87 runs with 24-bit precision control (found because arg3 = 0.9199999571 and not fround(0.92)): every operation rounds to float32, sin() is not rounded. With that, 120 of 120 argument sets match bit for bit given the guest's p and S. The table is a one-run capture (seed not reproduced).
- **Logo composite** 0x393fb..0x39441: logo buffer 0x10ce54 = logo.raw pixels +128 (255 stays transparent); out = logo==255 ? min(dst,127) : logo (table 0x1062b8). 60 frames exact (`cmp_blur.mjs` also checks it). **Palette**: 0..127 grey min(63,i>>1), 128+k = logo.raw palette k, all scaled by a fade that rises over about 150 flips (5 s) from black: floor(v*(k+1)/150) matches 789 of 800 sampled values (approximated).

## 0x243a9 solved (session 14): root cause = native 0x3c104 (array ctor helper) returned the wrong eax
- Trace chain (guest Unicorn vs JS, each ~4-6 min to present 714): no rand calls at all in frame 357 (the seed equality was a red herring); the 3279 clip calls (0x2c9ce) and 2101 line calls (0x2b9cd) were identical in both; the bolt is the *thick-line* polygon filler 0x2b50d (called from the wire-object drawer 0x1ea8f -> 0x1dcb6, 7 degenerate strips from the centre), whose input polygons differed. The object (88-byte `new`, built by 0x1e427) had its vertex array overwritten: JS object at 0x4002dd8 instead of 0x4002dc0.
- Cause: 0x1e427 does `eax=new(0x58); add eax,0x28; call 0x3c104 (array ctor, 3 elements of 12 bytes); lea ebx,[eax-0x28]`, i.e. the helper must RETURN the array start. `ARR` in `re/pre.js` left eax = whatever the last ctor returned (last element), so the object pointer was +0x18 and overlapped its own vertex array. Fix: `ARR` ends with `eax = p0` (applied in `re/pre.js` and in `web/js/sqr.gen.mjs`).
- Result: 0x243a9 **1138/1138 frames bit-exact, DAC exact**, 54 ms/flip in node; packed `web/assets/rc243.bin.gz` (1.35 MB, `re/rcpack.sh` pages-read recipe, `rc_scene_test` 1138 frames + 5 seeks 0 differing); RCS row {T:132.80,N:1138,a:'rc243'}; uitest draw check at 145 s.
- Lesson: an "uninitialised memory" hypothesis was wrong here; when a thin diff is in an otherwise exact scene, log the *inputs of the last routine that consumes data* (polygon list at 0x2b50d) in both runs and walk upstream, rather than diffing heap pages.
